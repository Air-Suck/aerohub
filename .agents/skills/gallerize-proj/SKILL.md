# Gallerize Proj

将一个算法项目整理成可核查的 Gallery 页面。先读仓库约定及 `gallery/README.md`，核对 Git 差异，保持增量修改。需要建立能力与进程映射时使用 `uav-architecture-analysis`。图中的层级按项目主架构表达职责，不改变实际进程与部署边界。

## 三层架构视图

算法项目的图统一覆盖 **Tool / Behavior / Function** 三层。算法接入范围在 Tool 及以下，但覆盖哪些层需按实际接入核查，不能由算法名称或单一分类标签决定。分别记录上游提供的能力与本项目实际采用的模块，在各层区分项目提供的实现、调用的执行能力、复用的数据与基础能力。

- **Tool**：规划、适配、执行协调及其他任务能力。现有 Planner 链只能标为 Navigation Tool 的实现基础，通用 Tool 未实现时须注明。
- **Behavior**：实际调用或扩展的基础执行能力，注明组件、Action、调用方与时机。区分算法新增实现、公共扩展和原生复用。
- **Function**：状态估计、环境感知/建图、控制与传感器等基础能力。区分算法实际提供的能力与其复用的外部依赖；例如定位建图项目可以同时覆盖 State Estimator 与 Perception。

未涉及的层或能力明确留空或弱化标注；调用、依赖某层不等于实现该层。不强制所有算法绑定运动 Behavior。执行调用与共享数据分别连线，数据可跨层直读。平台在三层图外注明边界；Mission/Agent 仅按实际状态说明。颜色与图例明确标识算法接入、公共复用及未涉及项。

## 源码核查

1. 读取用户指定项目的 README、版本锁定、配置与入口，沿实际调用追踪到 proxy、adapter、机群协调器及 Behavior。记录来源文件和符号；子模块未检出或没有日志时明确缺口，不自动初始化上游、构建或运行算法。
2. 建立各层模块的输入 → 输出 → 责任表，核实实现覆盖、执行调用与数据依赖。标明起飞等前置调用是否由测试/部署入口负责；不要把它写成算法核心自己调用。
   地图维护也纳入 Function 职责核查：地图可以与规划在同一进程中，按职责跨层绘制时注明共享进程。追踪地图输入是实际测量、仿真生成还是占位数据。共享代理不能作为集中式规划的证据，应继续核查逐机规划实例及广播关系。
3. 对多机项目，核实共享规划次数、车辆 ID/namespace、目标归属、轨迹时间与坐标转换、共同基时间、逐机 Goal、确认期限和失败收口。说明配置声明规模、展示规模和实际验收规模的区别；逐机调用不等于自动同步。
4. 区分源码核查、历史验收记录和本次运行证据。默认不运行 ROS、仿真或飞行任务。页面的验证等级遵循已有 schema，不能把结构图或配置目标解释为实际轨迹/测量结果。
   分别标明运行拓扑与目标部署：板端短程闭环不证明工作站任务调用已拆分，也不证明通用 Mission/Tool 已实现。以实际构建入口及来源记录确定算法实现版本；参考 upstream gitlink 不能替代主仓库 native 源码版本。无公开运行证据时，正文可引用主文档报告的限定结果，元数据仍使用 `unverified`。

## 内容落盘

- 所有网页内容与资源写入 `gallery/content/algorithms/<id>/`：`index.md` 保存 frontmatter 和正文，`assets/` 保存条目专属图示等小型资源。
- 在 `gallery/content/gallery.json` 的 `items` 中追加稳定 ID 与 `content/algorithms/<id>/index.md`，已有 ID 则原位更新，避免重复。
- 源 Markdown 可从仓库其他目录读取，但网页不得直接加载外部源文件；保留源文件原文。所有构建、监听和产物均限制在 `gallery/` 内，Skill 保持默认 `.agents/skills/` 路径。
- 默认不修改样式、模板或主文档。现有模板可承载的表格、图示和说明直接放 Markdown，不为单个项目扩展页面框架。

正文需要能回答：项目做什么；Tool、Behavior、Function 各涉及什么；哪些由项目提供、哪些调用或复用；多机如何实例化与协调；哪些事实已核实、哪些尚待验证。结构按项目选择，不机械复制不适用章节。

## 图示与视觉校验

SVG 保持原生可编辑，配标题、描述、Markdown 替代文字与对应文字说明。没有实际运行产物时使用结构示意。

1. **聚合重复实例**：Behavior、Function 等各层中，职责与接口一致的逐机实例优先用 `×N` 表示，并注明车辆或 namespace 范围。共享规划与协调只画一次；不同实现或调用关系分别画出。`×N` 表示独立实例数量，不表示一个进程，也不证明多机同步或该规模已验收。
2. **预留连线路径**：执行请求、结果数据和共享状态按图例区分。箭头接到节点边界，使用侧边或层间留白；连线避开全部节点文字、层标题、注释及无关节点，防止形成错误连接。需要连通的分支标出接点。
3. **渲染并查看**：SVG 修改后实际渲染并打开图片，检查文字裁切、线条遮挡、箭头归属和图例一致性；缩放到页面预计显示宽度检查可读性。每次调整后重新渲染查看，直到所有涉及节点与连线均可清楚辨认。XML 校验和构建成功不替代视觉校验；未实际查看时须如实报告未校验。

可使用 Gallery 已安装的 `sharp` 将 SVG 渲染为 PNG，写入仓库根目录 `log/gallery-review/`，再用图片查看工具打开。字体缓存不可写时将 `XDG_CACHE_HOME` 指向可写临时目录。预览须保留中文字体；缺字的渲染不能用于确认排版。证据图片属于运行产物，不复制进算法资源目录；正式 Skill 不依赖这些临时图片才能执行。

参考已核查案例：`gallery/content/algorithms/cat_ora/index.md` 及 `assets/layers.svg`。案例的版本、机数、坐标约定和验收结论只适用于该项目，不作为其他算法默认值。

其他三层图案例位于对应条目的 `assets/layers.svg`：`swarm_formation` 展示逐机规划与共享代理，`super` 展示同进程规划/地图及单机执行，`fast_livo2` 展示仅 Function 接入与共享算法的两路输出。按待展示项目选择参考，不复制案例的实例数量、运行后端或验收结论。

## Bundle 与交付

读取并执行同目录体系中的 `bundle-gallery` Skill，默认完成内容后自动本地 bundle。检查 Gallery 列表、详情、图示资源及站内链接，确认样式未改。交付时分别说明构建结果与实际视觉检查结果，给出预览产物路径及任何未检查项。开发服务的启动与效果验收按用户约定执行；本地静态构建和图片渲染不要求启动常驻服务。汇报源材料、三层覆盖与依赖、验证范围及待办；不自动推送或发布。

完成后把本次可复用的展示约束回馈本 Skill。算法复现经验归对应架构/适配/验证 Skill；仅做页面整理时不升级算法验收结论。
