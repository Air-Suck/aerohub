# IPADS-ROBOT-5G 远程连接

## 当前任务

确认如何连接 IPADS-ROBOT-5G 网络下的机器，并评估现有 SSH 主机和内网穿透方案。

## 已完成

- 2026-10-22 SSH代理核查（只读）：外层ssh进程28680实际建立`192.168.1.104:7245 → 202.120.40.82:22`；目标路由经WLAN、网关192.168.1.1，无活动TUN网卡或TUN默认路由。现有证据支持该SSH传输直连，未经过本机7892代理。链路顺序为本机→202.120.40.82→202.120.40.84→RKOH。隧道进程2536连接本机7892属于RemoteForward承载的上游访问，不代表SSH传输本身走代理。本轮未修改网络配置；结论限当前本机状态，未核查路由器透明代理。
- 本机 WLAN 当前连接 `IPADS-3203 2`，地址 `192.168.1.104`，尚未连接 `IPADS-ROBOT-5G`。
- 2026-10-21 扫描到的 SSID 是 `IPADS-Robot`（2.4 GHz，信号约 50%），没有发现名称为 `IPADS-ROBOT-5G` 的 SSID；本机已保存的 Wi-Fi 配置也没有该名称。
- SSH 配置已有 `IPADS_ROBOT`：目标 `192.168.1.239`、用户 `snh`，经 `3203-jump` 转发。
- 实测该配置失败：`3203-jump` 对 `192.168.1.239:22` 返回 `No route to host`；本机直连也超时。

## 有效结论

- 现有公网跳板机只有在它自身能路由到机器人 Wi-Fi 网段时才能作为跳板；当前证据表明不能直接使用。
- 连接同一 Wi-Fi 后应先获取目标机实际 DHCP 地址，再测试 `ssh 用户@地址`；不能假定 `192.168.1.239` 永远不变。
- 长期远程访问优先使用 Tailscale/ZeroTier；无软件条件时可让目标机向可公网访问的 SSH 服务器建立反向 SSH 隧道。
- 内网穿透的核心是让内网设备主动建立一条出站长连接；外部访问方通过中继或跳板复用这条已建立的连接，绕过 NAT/防火墙对入站连接的限制。

## 下一步

- 连接 `IPADS-ROBOT-5G` 后确认本机地址、目标机地址和目标机 SSH 服务。
- 若 Wi-Fi 开启客户端隔离，改用 Tailscale/ZeroTier 或反向 SSH 隧道。
