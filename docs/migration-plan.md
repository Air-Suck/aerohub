# 迁移实施计划

本计划自创建起进入实施；每个阶段必须有独立提交与真实验证记录。
交接入口见 [migration.md](../migration.md)。首批目标为 CAT-ORA，完整路线覆盖 Swarm 和 SUPER。

## 实施进度补充

CAT-ORA PC 已接入 FollowTimedPath，新增执行状态观察、正常/取消场景运行入口。
正常四机场景已完成到点、悬停、降落解除解锁；板端及 Swarm/SUPER 仍未验收。
一轮首轨迹到达前的失败及其恢复已保留，不将后续成功当作失败已根治。
最终场景结果、源码哈希和镜像 ID 见应用目录 migration-pc-validation.json。

## 版本管理

- 来源 b3be98e、目标 main b701e04；保留来源分支，使用独立 integration 分支。
- 现有未提交修改不自动纳入；不提交个人 SDK、设备地址、缓存和原始日志。
- 提交按依赖引入、路径归位、执行适配、部署、验收分类；不自动推送或发布。
- 源码、子模块、镜像 ID、板端安装哈希需可对应；迁移镜像使用新标签。
- 最终 PR 描述围绕最终行为重写，区分实际通过与仍未覆盖的场景。

## 阶段一：执行能力引入（进行中）

引入 main 的 FollowPath 独立扩展、时间线算法、Action/消息与客户端。
保持当前运行入口不变，先通过无 ROS 算法测试和原框架回归。
不迁入 main 旧 Gazebo 启动脚本。随后验证消息生成、扩展包编译和 fork ABI。
本阶段依赖引入不等于执行链已经迁移。

## 阶段二：按 main 归位源码

- src/planner/framework -> src/planner/framework，src/planner/interfaces -> src/planner/interfaces。
- 两算法 Adapter -> src/planner/<算法>/ros2_adapter；Humble 移植 -> 同级 humble。
- 上游源码 -> 同级 upstream，保留许可证与原始版本，不将移植伪装为干净上游。
- 活动 AS2/Pixhawk -> main 的 as2 布局，保留 fork 来源和保护修改。
- 单点输出桥归 legacy 执行后端；导航注册与环境转换按 perception 职责归位。
- 保留 AirSim/PX4 和现有部署入口；同步所有路径消费者及安装资源。

先搜索旧路径并分类：活动引用必须修正；历史证据保留原始路径且标明版本。
用 colcon 包发现检查重复包；核对 Registry 命令、Docker 上下文和板端复制清单。
ROS 包名、可执行名及已有 ControlPlanner 命令值保持不变。

## 阶段三：CAT-ORA 执行改造

数据流：Humble 算法 -> Adapter -> TimedTrajectorySegment -> 框架校验与逐机
FollowTimedPath -> Behavior 采样 -> 现有 AS2/Pixhawk -> 权威 AirSim/PX4。

- 默认 follow_path，legacy_setpoint 仅显式启用，不自动故障回退。
- 维护车辆与目标归属、输入新鲜度、慢 RPC 拒绝和原点转换约定。
- 共享 fleet 到逐机 odom 的转换仅做一次；PVA 与 yaw 一并核对。
- 缺失导数不能补为零；Behavior 推导导数与算法指定前馈必须明确区分。
- 计划生成时间、生效时间和参考计算时间分别处理；非最终段过期必须停止。
- Future 完成不等于停止完成；验证响应、Action/执行状态和模式反馈。
- 暂停恢复需要取消旧执行并重新规划，不继续旧时间轴。
- 模式丢失、迟到接受响应、服务异常和单机失败均需机群收口。
- 应用保留原生起飞降落，取消旧任务脚本中与 Behavior 重复的轨迹模式接管。

单机只允许一个运动参考源。新任务不得在旧任务停止未确认时接管。
不实现完整 Mission/Tool/Agent 或通用资源调度系统。

## 阶段四：构建和部署

PC 镜像显式构建接口与扩展包；OHOS 入口补充 Action 消息支持和依赖。
逐机只启动一个扩展 FollowPath，原生 Takeoff/Land 保留。
TF 隔离覆盖扩展节点；检查 frame 发布权，不修改既有坐标数值。
板端部署含新动态库、消息类型支持与 launch 资源，并核对来源哈希。
官方 OHOS builder、隔离 SDK 与目标依赖准备流程继续适用。

## 阶段五：验收门槛

1. 静态：无活动旧路径、无重复包，接口生成及安装资源完整。
2. 回归：原框架、CAT-ORA 数值/服务/输入适配测试通过。
3. 接口：错 frame、非有限值、缺失字段、迟到/倒序/重复、连续性和时钟回退。
4. 生命周期：取消、暂停重规划、迟到响应、停止拒绝/超时、幂等停止。
5. 多机：一机拒绝或更新失败时全机群停止，不能仅清理规划进程。
6. 底层：20/50/100 Hz 输入与既有固定输出频率、失流锁定和 NaN 契约回归。
7. 飞行：PC 单机，再 CAT-ORA 四机到点/取消/降落，再 RoboPi 与原混合拓扑。
8. 故障：规划断流、参考退出、定位过期、控制模式丢失。

沿用场景原阈值，不以放宽阈值通过验收。服务接受、加载、Action 成功和实际
闭环分别记录；设备测试仅针对明确隔离资源，不自动清理用户既有运行。
每项结果记录版本、环境、命令、退出码、证据路径及未覆盖范围。

所有消费者迁移并通过验收后再删除旧入口、更新发布清单。历史验证记录保留
原适用组合，不改写为新实现的成功证据。
