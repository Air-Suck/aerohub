# AirSim 共享链路诊断

`cloud_age_probe.py`是只读ROS观察器，按同一原始扫描时间戳配对原始点云、坐标注册输出和可选IPC诊断点云。它不解锁、不调用运动接口、不修改发布者参数。需已有部署及有效`/clock`；新建输出目录，不要把观察器的出现误认成域空闲。

```bash
# 在具有目标ROS消息环境的容器中运行，domain与被观测部署一致。
ROS_DOMAIN_ID=182 python3 deployment/airsim/diagnostics/cloud_age_probe.py \
  --namespace drone0 --duration 25 --output log/ipc/cloud-age/<new-observer>

# 已保存事件可在普通Python中重算，不启动ROS。
python3 deployment/airsim/diagnostics/cloud_age_probe.py \
  --events log/ipc/cloud-age/stages-01/events.json \
  --output log/ipc/cloud-age/<new-analysis>
```

输出包含分阶段年龄、相同stamp的接收时间差、未初始化时钟/未来戳计数、重复stamp与缺失覆盖。接收差包含DDS与观察器自身调度；ROS时间离散化，负差不等于数据时钟倒流。未匹配帧不冒充已测量阶段，缺少有效原始/注册样本会非零退出。`ipc/processed_points`在IPC第一次裁剪降采样后、历史合并前发布，不能当作完整地图安装完成时刻。

## 2026-11-11 点云年龄分析

分析了两轮已完成自由XYZ长任务录包，并对隔离AirSim/PX4/PC链做了一次未解锁地面观测。没有更改共享传感器、注册节点或算法参数。原始证据在`log/ipc/cloud-age/`；过程记录在`skill/temp/ipc/cloud-age.md`。

地面样本规模有限，不能直接替代运动下的TF与计算预算；不同阶段的p95也不能直接相加。观察器启动期间9条注册消息的ROS时钟尚未初始化，已显式计数并排除年龄计算；原始events保留，使用`stages-01-analyzed/report.json`，不使用最初未过滤时钟的report。

结论：当前年龄主要由**共享采集/发布链路中已有的帧年龄，加上约10Hz帧间重复使用**组成。地面原始点云到达时已旧约75ms，注册仅增加几毫秒；飞行IPC预处理也仅几毫秒量级，未发现数百毫秒的IPC专属计算积压证据。对复用该AirSim桥和navigation_inputs的消费者，这是共同输入条件；不能据此说所有算法、实机或跨板链路都固定延迟200ms。

仍未分离：AirSim缓存帧被取回时的相位等待、RPC/序列化、Python点云转换和DDS接收各自耗时。已核对固定镜像中的传感器node/worker/rpc和navigation_inputs源文件与仓库哈希一致。桥使用10Hz ROS时间定时取帧，worker只合并一个待执行请求，重复stamp不再发布；每次RPC新建TCP连接。这些是候选机制，不能直接把其中任意一项称为已证实的75ms根因。

本机AirSim参考源码将`update_frequency`与`RotationsPerSecond`分开，输出timestamp在点云生成后填写；下载场景二进制与该源码的编译对应关系未证实，因此这里只作核查线索。当前实测新帧约9.8Hz，不通过提高发布频率或修改时间戳伪造更新率。

后续优先在隔离地面环境补齐RPC请求/返回、转换/发布、TF就绪、地图安装与实际消费的原始时间边界，做**源扫描率不变、启动取帧频率10/40Hz**的单变量对照，测新stamp频率、首次拿到帧的年龄、重复获取次数、RPC/CPU代价。现有`lidar_rate_hz`只在创建timer时读取，运行中改参数值不会自动重建timer，应在启动时指定并用实际消息验证。先证明取帧相位是否主因，再决定是否需要连接复用、格式转换优化或TF/队列调整。

当前处理决定：在两次已通过的静态森林、名义3m/s任务中，尚无证据证明该年龄是主要瓶颈，先作为性能与安全余量指标保留，暂不修改共享参数；上述对照方案留待后续动态场景与性能优化。最终讨论记录见`src/planner/ipc/validation.md`。

## 最新帧年龄与地图历史分开

当前IPC积累最多十帧/两秒静态历史。约102ms帧间隔下，十帧覆盖约0.918s，较老观测在求解时可能已经超过一秒；`cloud_stamp`仅代表最新扫描，不能说明地图中每个点都同样新鲜。

已注册的静态点仍处于世界坐标中的原位置，历史有助于覆盖遮挡和有限视场。动态环境则需要按区域/体素记录最后观测、占据与清空证据，单独处理过期和动态物体；单纯删除所有历史会损失静态覆盖，也不会消除新扫描在采集链路中的等待。

3m/s下192ms对应约0.576m前进，是环境新变化尚未被感知时的运动量级；它不是既有静态地图点必然错位的距离。共同改进应围绕端到端时间契约和测量链，而非给每个算法各自改now、扩大队列或提高发送定时器。
