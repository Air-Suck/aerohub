# 平台传感器与算法输入适配

## 职责与分层

目标是让平台实际输出的测量满足算法的输入契约，而不仅是话题类型匹配。读取项目约定、平台版本、传感器配置、实际发布代码和算法消费者；不得仅按组件名称决定适配方式。

- 平台驱动或传感器桥负责对接设备 SDK、AirSim RPC、PX4 数据通道，输出有明确语义的测量。
- 算法输入 Adapter 负责必要的格式和坐标转换；共享处理尽量复用，特有预处理留在算法边界。
- 状态估计与感知算法都可直接消费测量。Tool、Planner 也可订阅明确的数据接口，不必经过 Behavior；避免各自重复实现平台 SDK 接入。
- 状态估计输出自身状态，环境感知输出地图、点云或检测结果，两者可由同一算法产生，但应分别提供给对应消费者。不强制统一所有地图表示。
- 运动控制继续通过 AS2 控制/平台层到 PX4；传感器数据不要求全部绕经 PX4，也不允许用 AirSim 运动 API 绕过飞控来完成运动验收。

复用局部地图时核对查询实现，不能凭函数名推断语义：当前 ROG-Map 在关闭未知膨胀时 `isKnownFreeInflate` 仅返回非占据，要求真实已观测自由应另查概率地图的 `isKnownFree`。扫描须使用匹配原观测时间的射线原点；自身传感器盲区与未观测远处空间分开处理，核对起飞/移动后自身附近是否仍被错误标为未知。维护自身盲区时保留实际占据证据，不用清空远端未知区域解决规划失败。私有地图副本保留来源、许可证、配置差异及修改，不能自动宣称与原 Planner 地图条件完全相同。

## 与已有 Skill 的边界

本 Skill 决定“从平台取什么数据、数据是否具备所需物理语义、如何进入算法”。ROS 发行版、消息生成、跨 ROS 传输和 QoS 的实现使用 [ROS 适配](../uav-ros-adaptation/SKILL.md)；AS2 插件发布与宿主生命周期使用 [AS2 接入](../as2-extension-integration/SKILL.md)；完整下游效果和故障验收使用 [端到端验证](../uav-sim-e2e-validation/SKILL.md)。不要分别维护相互冲突的时间、坐标或话题配置。

## 先交付数据契约，再实施转换

对每条输入记录以下内容，无法证实的项标为未知，并说明验证方法：

| 项目 | 必须确定的内容 |
| --- | --- |
| 来源与消费 | 传感器/平台版本、驱动或 RPC、实际发布者与话题、算法订阅入口；测量、滤波数据、估计状态或真值 |
| 字段 | 单位、类型、有效范围、缺失语义、协方差、二进制布局及算法实际读取的字段 |
| 时间 | 采样/积分/扫描起止/发布时刻、时钟域、延迟、频率与抖动、重复/乱序/暂停/reset 处理 |
| 坐标与标定 | ENU/NED、FLU/FRD、光学系、frame_id、外参方向、TF 权威发布者、内参/畸变及来源 |
| 传感器模型 | IMU 比力/角速度及处理历史；图像曝光与编码；雷达扫描模式、逐点时间、ring 和去畸变假设 |
| 可用性 | 丢帧、断连、重启行为、图形/算力要求、多机命名空间和数据源隔离 |

核查算法源码是否使用额外假设，如固定扫描角速度、同一 IMU 的积分结果、相机曝光时间。相同 ROS 消息类型和 PCL 转换成功不构成语义兼容证据。

## 选择最小适配

1. 优先复用平台、AS2 或已有算法的匹配接口与预处理器。仅名字相似不够，核对实际配置及实现。
2. 坐标、编码或字段可无损转换时，在 Adapter 显式实现并记录变换。改 frame_id 不能代替变换；改成 now 不能修复同步。已去畸变点云不得再按原始扫描假设重复去畸变。
3. 缺失信息不可凭空恢复：不制造扫描线、逐点采样时间、测量强度或协方差。算法允许的默认值须标为占位属性，并验证不会被误当作测量。瞬时整帧与旋转扫描分开处理。
4. 若现有接口无法满足，选择有证据支持的传感器配置、独立预处理入口或可重放上游补丁。说明语义损失与适用范围；不可验证的候选保持待验证，不为得到通过结果关闭算法必需输入。
5. 平台事实不可得时，继续可独立完成的接口检查；不能据未知条件宣称已接入。当前 AirSim 场景先读 [平台核查要点](references/airsim-px4.md)。

## 验证与交付

深度图接模型前，分别核查单位（`32FC1` 米或 `16UC1` 毫米）、端序、行 padding、零/非有限无效值、采集 stamp，以及训练相机 FOV。resize 只改变像素网格，不校正 FOV 或外参。可复用 `deployment/inference/tests/test_contract.py` 验证格式转换；该测试属于合成接口证据，不证明 YOPO 已消费真实 AirSim 相机或相机与规划系已经对齐。

官方发布的不同checkpoint可能对应不同仿真器与预处理。逐一核对其实际运行配置、
裁剪比例、相机pitch和深度来源，再计算裁剪后的视场；不能把同项目另一个模型的
相机参数直接套用。DiffPhys高速发布源码包含Flightmare相机配置及中心裁剪，而
swarm评估使用AirSim；去掉裁剪的全幅实验应单独命名，不因单轮导航改善就宣称等价。

对双目深度追踪匹配器输出类型、视差范围与亚像素支持、baseline和焦距、无效视差
编码、bf/disparity转换、整数毫米截断及最终发布话题。DiffPhys高速发布的
flightmare_bridge使用8位整数视差，0/255记无效，毫米mono16输出；Planner再转米并
将0替换24m。连续理想深度与其在单位上可兼容，但生成分布仍不同。分别量化毫米
传输和整数视差影响，不将理想深度量化或加噪声称为完整SGM复现。
若专项启用双目，记录两相机同步、实际基线、光轴深度/射线距离及额外采集时延；
普通单深度相机基线不因调查而默认增加无关采集。

FOV注释与渲染器文档不一致时，追踪中间桥的转换及深度反投影焦距。
Agile Autonomy的Flightmare桥将配置水平角转换成渲染器垂直角，两种约定可同时正确。
中心裁剪按源码整数取整，nearest按实际索引规则验证；若将点式归一化移过采样步骤，
用非均匀深度、无效值及连续模型输出证明等价。源CameraInfo保留原始几何，
模型张量的尺寸不反写为源标定。提高源分辨率后重新测量采集到消费的时延与唯一帧率。

复用其他Demo场景时，核对模拟器启用项、各容器采集进程和实际下游消费者三者。
没有点云消费者的视觉任务可在专属配置关闭LiDAR模拟与重复ROS读取；仅关闭相机
桥开关不会停止LiDAR。保留飞控必需传感器及任务必需输入，记录实际worker清单。

先用非恒等坐标、已知单位与时间样例验证转换和错误拒绝；再取实际平台消息，测量频率、时延、字段和同步。随后运行真实算法，确认输入被消费、输出有效并被实际下游使用。状态算法检查运动下的误差与漂移；地图检查运动下障碍稳定性和查询/规划消费。阈值在运行前按算法需求确定。

频率验收同时统计接收消息数和唯一采样时间戳数。平台桥可能高频重复发布同一状态；topic 工具显示的消息率不能证明控制获得了同等频率的新测量。重复 stamp 可按契约静默丢弃，倒序、未来或过期 stamp 应单独计数。多源状态组合还需测量配对误差，并证明组合后的 canonical 状态频率满足实际消费者 freshness。

源码审查、预处理测试、合成数据、实际平台采样、算法运行和运动闭环分开报告。真值只用于明确标注的评分或测试输入，不能偷偷替代待验收算法。GPU 是算法运行条件时必须执行真实 GPU 测试；GPU 暂时缺失只能使复现保持未完成，条件恢复后补测。当前开发主机已有 GPU，不得用关闭相机、NullRHI、CPU mock 或合成算法输出冒充实际平台验收。

交付数据来源与契约、桥接/预处理代码、参数与标定配置、启动入口、版本、复验命令、证据及未覆盖项。平台专用桥放 `simulator/airsim/`；算法专用适配按 `src/state_estimator/`、`src/perception/` 现有归属组织，联合算法不复制两份；跨组件编排放 `deployment/`。过程记录放 `skill/temp/<任务>/`，原始证据放 `log/`。能力卡片位于 `cards/`，按本次实际变动维护输入依赖与验证状态；不把个人机器信息写入正式 Skill。

## 低频图像与高频定位

图像采集时刻应匹配有界定位历史中的测量快照，而不是在每次规划 timer 上与最新定位比较。独立检查当前定位新鲜度、图像新鲜度和该快照的同步偏差；用图像5 Hz、定位50 Hz的回归验证正常帧间周期仍可规划，且过期图像会停止。YOPO 实际接入曾因比较最新定位而拒绝正常目标，修复采用历史匹配，未放宽50 ms偏差门限。

对针孔深度相机，用内参/画幅计算实际水平与垂直 FOV。训练网络的像素尺寸不自动代表训练几何；例如90°水平视场下160×96约为61.93°垂直视场。DepthPlanar 视轴深度与 DepthPerspective 射线距离分别核对。共置与 pitch-only 外参是特定首期接入约束，非零杆臂需另行处理，不能推广成所有相机的默认物理模型。

速度等测量依赖同采样时刻的动态 TF 时，消息可能先于 TF 到达。保留有界原始测量队列，在原新鲜度上限内重试变换；保持时间戳，不以最新TF或now替代。仅在输入确实陈旧、持续无法匹配或覆盖耗尽时收口。YOPO 实际失败的分项年龄曾为深度75 ms、位姿21 ms、已接纳速度300 ms；动态TF落后速度40 ms的真实ROS回归检出了直接丢弃策略，修复后通过。

若权威接口明确保证Pose和body Twist共享同一测量stamp，可用严格配对的权威姿态作坐标旋转，避免依赖重复动态TF流；先核对真实发布源码，不将这一约定套给任意话题。AS2当前`publishTwist`以同一stamp发布姿态，YOPO据此保持同一状态源并等待配对；其他固定父系仍需相应时间TF。即便有队列，TF持续不可用也必须保留失败事实，不能仅靠等待掩盖。

视觉策略接入不同仿真机体时，先保存起飞后原始深度并统计近场返回的空间分布，检查相机是否看到机体或桨叶。更换相机杆臂须同步场景配置、真实TF和算法校验并重新验收；不以遮罩近距像素冒充传感器几何等价。DiffPhys的官方SimpleFlight杆臂在本PX4场景出现近场返回，显式前移后单轮短程通过；这是平台特定证据，不能推广为统一相机位置或唯一故障原因。

## 评分真值桥

评分用真值桥与飞行控制链隔离，并使用非恒等位置和姿态样例独立回归。NED/FRD 到 ENU/FLU 的轴交换、符号和航向零点必须与平台状态转换逐项交叉核对；不能因消息 `frame_id` 正确或静止点重合就认定转换正确。错误的真值桥不会影响算法飞行，却会系统性扭曲所有精度结论，因此原始平台值、转换后值和回归结果都应进入证据包。
