# HDC Helper

- 从现有配置、PATH 和已知 SDK 位置查找 hdc，确认后复用；按需查看本机版本和帮助，不硬编码本机路径或设备序列号。
- 优先使用任务已指定的设备；仅一台在线时自动选择，后续显式使用 `-t`。多台且无法判断目标时再询问。
- 连接正常时直接执行任务，复用已确认的信息。优先非交互命令；日志读取限定范围或时长。
- 区分本机与板端的转义、变量和重定向。复杂命令可传临时脚本执行；不假定板端有 Bash、sudo 或完整 GNU 工具。
- 所需环境在同一次远端执行中加载；分别确认 HDC 传输结果与远端命令结果，不把客户端成功退出当作业务成功。
- 按操作设置合理超时，恢复和重试次数有界。超时后先核对远端是否仍在执行或已完成，再决定重试，避免重复写入或启动进程。
- 多个小文件按需打包传输，重要产物校验完整性。只操作当前任务的文件、进程和端口转发，完成后清理自己的临时资源。
- 在已有授权范围内自行排障，优先恢复当前目标连接。重启全局 HDC 服务、重启设备、提权或改系统分区前，确认属于当前授权范围。
- 仅在目标无法判断、需要人工授权或插拔、确实缺少必要信息时询问用户；说明具体阻塞原因及最少需要的操作。

HDC 可达与 ROS/DDS 网络可达分别检查。直连板卡时，板端有配置地址、网口 carrier
正常也不代表 PC 已获得 IPv4；先核对两侧地址与主机路由，再决定在哪一侧补齐。
板端精简系统可能只有 `ifconfig` 而没有 `ip`。PC 的网络修改还受本机 sudo/Polkit
权限约束；HDC 的板端权限不赋予 PC 管理权限。权限缺失时交接最小主机操作，
不要用 HDC 配置另一个板端地址冒充修复主机地址，也不要改动无关 Wi-Fi/默认路由。
