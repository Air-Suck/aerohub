# 组件打包、注册与部署管理

## 输入与边界

读取项目约定、实际实现、构建产物、能力卡片与验收结论。组件清单回答“安装运行什么”，能力卡片回答“提供什么、如何选择使用”。不因生成了清单就声称已有注册中心、调度器或自动回滚实现。

## 清单内容

复用项目已有格式；没有格式时采用明确版本的 YAML 初稿，不冒充 AS2 原生规范。至少说明：

- 稳定组件 ID、版本、源码/补丁、许可证、镜像与架构、完整依赖及外部前置条件。
- 提供的 capability IDs 和 `cards/` 路径；共享进程、共享设备与不可独立启停的能力组。
- 入口、配置、标定要求、挂载、持久化目录、命名空间、时钟、端口、算力和传感器要求。
- 生命周期、依赖就绪条件、健康/数据新鲜度、停止确认、失败与回滚处理。
- 状态/TF 发布权及资源冲突、用户权限、已验证场景和证据版本。

## 部署流程

1. 检查目标环境、依赖、输入表示与消费者匹配。缺少传感器或有效标定不能仅启动空进程后标健康。
2. 先隔离验证启动、真实输入消费与输出新鲜度，再接入既定消费者。发现现有能力冲突时不要默认覆盖。
3. 依赖按就绪状态启动，不只依赖固定 sleep；健康区分进程存活、算法初始化、数据有效和任务可用。
4. 切换权威状态或运动提供者时，检查消费者停止、旧发布者退出、TF 与时间连续性和新来源就绪。若尚无无缝切换机制，明确要求停止任务后切换，不虚构热切换。
5. 更新失败时按明确版本恢复，并再次检查发布权与健康；回滚可能不能保留地图/估计内部状态，须说明重初始化影响。

## 交付

提供清单、启动/停止/检查命令、参数示例、更新回滚方法、能力卡片关联及证据索引。已有部署脚本优先复用；不要替用户擅自部署到飞行设备或修改运行中的系统。

能力卡片分工由卡片编写 Skill 负责；没有可用 Skill 时按本节关系检查而不阻塞。记录进入 `skill/temp/<任务>/`，产物进入 `log/`。本初版定义交付要求，不意味着当前 Model Hub 的注册、安装和回滚系统已实现。
