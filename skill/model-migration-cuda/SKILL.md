# CUDA 模型迁移与准备

本 Skill 是模型准备流程的唯一维护入口。[可复现构建](../uav-reproducible-build/SKILL.md)与[组件部署](../uav-component-deployment/SKILL.md)遇到模型迁移时读取本文件，完成后继续各自主流程。单独调用时仅处理用户指定模型；ROS 接口、平台输入和部署启停按实际任务另用对应 Skill，不自动扩展范围。

## 1. 核对基线与归属

读取项目约定、现有模型入口和真实导入链，记录算法提交、本地修改、Python/框架版本、权重来源和校验和、预处理与输出语义。保留原环境与固定输入输出作为迁移对照。

算法调用 Inference 不改变源码分类。例如 YOPO 的 upstream 在 `src/planner/yopo/upstream/`，模型模块在 `src/inference/models/yopo/`；引用算法实现，不复制网络或把整个 Planner 搬入 Inference。明确模型返回的是候选状态、轨迹还是控制量。

完成条件：源码与模型文件可追溯，需保留的本地修改已明确，未知硬件/输入条件已标记。

## 2. 收束独立环境

每模型在 `src/inference/models/<模型>/` 维护 `pyproject.toml`、`uv.lock` 和忽略的 `.venv/`。依据推理真实导入保留依赖，不直接安装上游全部训练、ROS、仿真和可视化依赖。公共 FastAPI runtime 使用仓库相对路径依赖；ROS Adapter 留在独立 ROS 环境。

在新位置从锁文件重建环境，不直接移动旧 venv。固定适合该模型的 Python 版本及 CUDA wheel 来源，默认用 `uv sync --locked`；更新锁文件作为显式依赖变更验证。不要将 YOPO 的 Python/CUDA 基线推广成其他模型默认。

若出现同版本 CUDA 包重复下载，检查锁文件与已有缓存的 wheel 来源。PyPI 与 PyTorch CUDA 索引可对应不同缓存；需要固定传递运行库来源时，可将相应依赖显式声明，再配置 `tool.uv.sources`，检查生成锁文件的 source。

完成条件：模型依赖与 ROS 环境分离，锁文件可解析，运行不依赖旧工作区或系统残留 Python 包。

## 3. 提供模型自己的准备入口

每模型必须交付 `README.md`、可执行的 `setup.sh` 以及模型文件校验清单。README 说明前置环境、源码/权重来源、准备与启动命令、配置项和验证边界；包的准确版本以依赖文件为准，避免文档复制完整依赖表。

`setup.sh` 按以下顺序准备：

1. 相对自身定位仓库和模型目录，检查源码、受支持版本及 uv。源码缺失时给出初始化方式；保留已有 checkout 和修改，不自动切换版本。
2. 按声明来源准备模型文件到本模型忽略的 `artifacts/`；校验来源与目标。已存在且正确的文件复用，不符时明确失败，不静默覆盖。外部下载先写临时文件，校验后再放入目标位置。
3. 显式将 `UV_PROJECT_ENVIRONMENT` 指向本模型 `.venv`，再同步锁定依赖，避免调用者环境变量改变安装目标。
4. 加载准备好的默认权重并预热。CPU 检查仅在模型支持时执行，明确标为准备检查；CUDA 另提供 `--check-cuda` 或等价入口，要求真实 GPU 加载/预热成功，不静默降级。

准备脚本不启动 HTTP/ROS 服务，不安装系统驱动、不修改其他模型环境。运行默认权重路径与准备产物一致；运行时的自定义权重覆盖与默认文件准备分开。

完成条件：从仓库外目录执行成功，重复执行不改写正确模型文件；模型文件和 venv 均被忽略，已有环境及源码修改保留。

## 4. 分层验证与交付

- 在 `src/inference/manifest.json` 登记稳定模型 ID、仓库相对模型目录及描述。manifest 只声明支持集合，不复制各模型版本/依赖/权重清单。用户配置统一用 YAML，优先在已有用户配置中维护 `inference.models` 模型 ID 列表，通过 `--config` 指定。先核对现有入口，无法确定统一配置路径时明确询问；不把模型选择混入 ROS 参数或有严格 schema 的资源路径配置。可提交片段为 `config/inference.example.yaml`，默认独立本地 YAML 路径为 `config/inference.local.yaml`，不覆盖已有用户文件。
- 复用 `deployment/inference/setup_models.py` 按配置调用模型 setup。先用 `--list` 核对支持集合、`--dry-run` 检查选择；未知/重复模型在执行前拒绝，空列表不操作。实际准备只作用于所选模型，失败停止，不卸载未选模型或启动服务。
- 对照迁移前固定输入，比较所有候选、评分和元数据，而非只比较最佳候选；阈值在运行前按模型要求确定。
- 分别记录依赖同步、CPU 加载/预热、CUDA 加载/预热及服务链路结果。CUDA 探测在实际运行权限下进行：受限沙箱内不可用不能直接推断宿主驱动故障。
- CUDA 预热不等于 GPU 的 ROS 往返、真实传感器或 AirSim 验收。进一步服务验证使用[端到端验证 Skill](../uav-sim-e2e-validation/SKILL.md)，保留未覆盖项。
- 向组件清单交付准备入口、模型文件路径/校验清单与环境锁位置；更新能力卡片中的实际证据范围。过程记录在 `skill/temp/<任务>/`，原始日志与运行产物在 `log/`。

具体模型的实现、版本、权重和复验命令留在其模型目录；模型接入提交后才将其登记到 manifest 并添加正式实例链接。通用流程不依赖忽略目录中的历史记录或尚未提交的模型实现。

完成条件：模型目录可独立说明并重现准备流程，证据范围准确；后续通用改进集中更新本 Skill，调用方仅保留触发条件与链接。
