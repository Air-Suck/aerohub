# 无人机工作架构分析

## 输入与范围

获取用户目标、上游仓库及版本、论文或说明、目标 AS2 版本、下游消费者和硬件约束。先读项目 AGENTS.md 与开发者贡献指导；版本或需求未知时标明未知，不将论文中宣称的能力当成源码已经实现。

本 Skill 产出接入设计，不自动实施重构或部署。

## 分析方法

1. 从启动入口追踪真实订阅、算法调用与发布点。建立表格：能力、输入、输出、消息实际字段、时间与坐标语义、消费者、源码位置。
2. 按[四方部署职责](../../docs/项目简介.md#deployment-roles)列出角色→设备/环境→进程/包→接口；该约定适用于全部组件，PC 共置是部署选择。区分目标约定与当前实现，单独记录各项目的迁移和验证状态。区分算法能力、接口、进程和部署组件。一个联合算法可以输出多种能力，不因目录分层而拆散优化过程或复制源码。
3. 映射职责：Planner 生成计划，Behavior 执行计划，State Estimator 提供自身状态，Perception 提供环境表示；Tool 是面向任务的入口，可组合这些能力。输出轨迹不是 Behavior，而是执行请求的数据来源。
4. 检查锁定 AS2 的接口及实现，列出可直接复用、需扩展和需独立实现的部分。仅改话题名、丢弃时间信息或把三维地图投影为二维，不算语义等价复用。
5. 明确状态与 TF 发布权、共享进程、启动依赖及资源冲突。多个地图表示可以并存；同一权威状态接口不能无仲裁地竞争发布。
6. 拆开滚动规划与执行timer时，追踪timer是否同时维护下一次规划的参考p/v/a/yaw。保留实际生效revision与参考状态来源，并区分观测时刻、规划起点和未来交接时刻；去掉控制发布不等于可以去掉这份规划输入。检查未来接续处完整PVA/yaw及迟到拒绝语义，不以仅修改时间戳或放宽门槛代替接续设计。

## Inference 依赖与算法归属

算法调用推理服务不改变源码归属：YOPO 的上游仍在 `src/tool/navigation/planner/yopo/upstream/`，`src/basic_function/inference/models/yopo/` 只提供网络适配和独立环境。公共 Inference Function 对外 ROS、内部 FastAPI；不要为依赖关系迁移或复制 Planner。核查输出是张量、候选终端状态、完整轨迹还是控制量，候选状态与评分不自动具备轨迹重建和 Behavior 执行能力。

联合定位建图组件按主要源码职责选择唯一归属，其他能力目录只放接口说明或适配层。分别建立 State Estimator 与 Perception 能力卡片，但用同一组件 ID、共享进程组和耦合启停约束关联；“可分别选择能力”不等于算法可以分别启动、重置或升级。地图可视化锚点、配准点云和完整隐式模型也要分别命名，不能把便于传输的点集提升为占据图、ESDF 或完整地图。

对循环策略，追踪实际调用处的网络维度、隐状态输入输出、更新频率和动作后处理，不以模型构造器默认值作为部署契约。区分训练模拟器和官方评估入口；缺失评估代码或权重时，先列为迁移前置条件。明确每车/每任务隐状态的归属、复位、请求顺序及超时结果是否提交，避免跨任务污染。策略输出控制量时，不假定可套用候选终端状态的轨迹重建；接入 FollowTimedPath 前须论证动力学、时间和滚动接续语义，缺少证据时保留执行方案待定。

速度策略接入有限位置目标时，分别核对高度意图、速度大小和停车职责。列出网络实际观测是否包含高度误差、官方部署是否只输入固定方向速度，以及高度是否另有执行闭环。加入目标前视距离后，逐式检查方向调整与速度调度的耦合：若先缩短相对位置，再使用 `min(相对距离, 目标速度)`，前视距离可能同时压低期望速度。用固定状态对照并记录实际输入向量；较慢飞行通过不能作为原目标速度能力通过的证据。训练入口和发布 checkpoint 的部署入口分别核查，训练源码的损失项不自动证明发布权重具有定高能力。

核查学习策略的高度约束时，分别追踪训练损失、场景几何、部署动作后处理和评估终止条件。沿总损失表达式确认系数实际参与方式，不能由参数默认0或legacy注释推断该项关闭；说明高度惩罚的坐标零点与地面位置。边界越界后记失败属于验收条件，不等于飞行中有高度保护。公开训练入口与发布权重缺少训练记录关联时，保留该不确定性。

跨仿真器复现性能前建立配置对齐门槛：锁定权重实际部署入口，逐项记录机体/执行器、控制更新率与响应、状态来源、传感器几何与误差、策略频率、输出包络及任务引导。参数文件须追到启动加载点；提取目录缺文件时回查完整归档。不同控制器增益数值不可直接等同；用独立响应指标验证，并记录实际运行参数。任一性能相关项未核实，保留未完成并优先补配置证据，再进入性能调优；理想传感器也不自动保证对学习模型更有利。

## 交付

给出能力映射表、最小数据/调用链、源码与适配目录归属、复用决策及理由、待核查条件。说明哪些输出供 Tool 查询，哪些构成执行控制链。后续 ROS 兼容、AS2 实现、部署和验收分别消费这份设计。

复现过程写入 `skill/temp/<任务>/`，证据产物在 `log/`。遵循项目收尾要求更新相关 Skill；新增未约定 Skill 先在对话中提出必要性，不自动落盘。

## FAST-LIVO2 案例与边界

官方 ROS 1 实现可保持一份源码、一个联合定位建图进程：自身位姿速度接入 AS2 State Estimator，配准点云通过 Perception 提供。它们是两种能力，不等于两个可独立启停的算法。点云不自动等于完整地图或 ESDF。既有案例仅达到编译、契约测试和合成输入执行冒烟，不能推导出真实数据或飞行验收通过。

PIN-SLAM 同样保持单进程：全局修正位姿进入 State Estimator，神经点锚点进入 Perception。锚点 PointCloud2 只是隐式模型的支撑点，不等于可查询 SDF、碰撞地图或序列化模型；需要这些能力时另建明确的查询、转换或持久化接口。
