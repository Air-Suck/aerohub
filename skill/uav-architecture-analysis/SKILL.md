# 无人机工作架构分析

## 输入与范围

获取用户目标、上游仓库及版本、论文或说明、目标 AS2 版本、下游消费者和硬件约束。先读项目 AGENTS.md 与开发者贡献指导；版本或需求未知时标明未知，不将论文中宣称的能力当成源码已经实现。

本 Skill 产出接入设计，不自动实施重构或部署。

## 分析方法

1. 从启动入口追踪真实订阅、算法调用与发布点。建立表格：能力、输入、输出、消息实际字段、时间与坐标语义、消费者、源码位置。
2. 区分算法能力、接口、进程和部署组件。一个联合算法可以输出多种能力，不因目录分层而拆散优化过程或复制源码。
3. 映射职责：Planner 生成计划，Behavior 执行计划，State Estimator 提供自身状态，Perception 提供环境表示；Tool 是面向任务的入口，可组合这些能力。输出轨迹不是 Behavior，而是执行请求的数据来源。
4. 检查锁定 AS2 的接口及实现，列出可直接复用、需扩展和需独立实现的部分。仅改话题名、丢弃时间信息或把三维地图投影为二维，不算语义等价复用。
5. 明确状态与 TF 发布权、共享进程、启动依赖及资源冲突。多个地图表示可以并存；同一权威状态接口不能无仲裁地竞争发布。

## 交付

给出能力映射表、最小数据/调用链、源码与适配目录归属、复用决策及理由、待核查条件。说明哪些输出供 Tool 查询，哪些构成执行控制链。后续 ROS 兼容、AS2 实现、部署和验收分别消费这份设计。

复现过程写入 `skill/temp/<任务>/`，证据产物在 `log/`。遵循项目收尾要求更新相关 Skill；新增未约定 Skill 先在对话中提出必要性，不自动落盘。

## FAST-LIVO2 案例与边界

官方 ROS 1 实现可保持一份源码、一个联合定位建图进程：自身位姿速度接入 AS2 State Estimator，配准点云通过 Perception 提供。它们是两种能力，不等于两个可独立启停的算法。点云不自动等于完整地图或 ESDF。既有案例仅达到编译、契约测试和合成输入执行冒烟，不能推导出真实数据或飞行验收通过。
