# 迁移无人机 Planner

本 Skill 只保存 Planner 特有决策，通用工作交给对应 Skill。过程记录在 `skill/temp/<planner>/`，证据在 `log/<planner>/`。

## 1. 冻结 Planner 能力

沿真实入口确认 Planner 是批处理/滚动、单机/多机、全局/局部，并识别输出为几何路径、时间化轨迹、候选状态、控制量或策略动作。完成 [Planner 契约](references/planner-contract.md)，冻结首个能力切片和排除项。

先核对上游实际地图来源及用户期望的传感器链路。上游使用完整静态点云，不代表目标任务允许使用仿真器导出的全场景碰撞图；上游只消费地图，也不代表其自带 LiDAR 建图或滚动规划。传感器建图与在线规划的缺口应明确记录，不能靠替换成全局真值地图来宣布用户目标完成。先验地图可用于独立算法基线或诊断，结论须限定到该输入条件。

能力声明、论文系统及仓库示例分别核查；示例用 mockmap 不能推出方法不支持未知环境。用户选择未知环境局部规划时，移除任务入口中的全场景先验依赖；若现有适配缺少自由/未知空间表示、局部目标、地图更新或运动中交接，应如实报告暂不支持。保留上游与历史证据，不把传感器快照替换到全局长程规划入口就视为局部规划完成。

复现优先保留上游算法语义并回答用户性能目标。区分用户要求、上游基线、工程观察指标与必要的执行保护；不得默认把自行提出的精度、瞬时超调容差或重复次数升级为用户目标的硬门槛。例如“约 3m/s”应报告巡航速度、峰值及任务结果，不自动解释为超过 3.15m/s 即中断。额外工程门槛不能让复现退化为围绕自定数值的控制调参。

**完成门：** 状态、目标、环境、约束、计划、完成与停止语义均可追到源码或明确标为未知。

## 2. 迁移 Planner Component

使用 [`uav-migrate-component`](../uav-migrate-component/SKILL.md) 锁定上游、建立基线、迁移核心、构建 PC 版本、完成数值对照并建立 Function/Behavior Harness。GCOPTER 等普通 C++ Planner 不因 ROS wrapper 简单而跳过上游基线。

Planner 作为 Function 产生计划；执行由已有或扩展 Behavior 承担。轨迹转换保留中间点、时间、P/V/A/yaw、车辆对应和共同时间基准。控制量或策略动作先定义对应执行模式，不伪装成轨迹。

批处理覆盖无解、边界与地图 reset；滚动覆盖 revision、未来交接连续性、迟到与任务世代；多机覆盖身份、同步和部分失败；策略覆盖频率、隐状态、watchdog 与停车。

将批处理优化器用于局部规划时，保留独立的环境查询、局部目标/路线及重规划调度，不因复用地图就默认复用另一 Planner 的规划算法。用户允许先复制地图实现时，可维护带来源和许可证的私有副本，不强行先抽公共模块。首次静止边界与运动中未来 P/V/A 交接分别实现；仅收到执行接受确认后才更新已承诺的轨迹基准。远端新障碍应触发替代规划，不能把每次地图变化都等价为整段任务失败；交接前缀受阻和替代规划失败则按声明的停止机制处理。实际求解耗时、地图更新率和执行交接延迟共同决定可用的重规划周期，不能只用定时器配置频率代表实际更新能力。

以已验收的参考 Planner 作为同场景基线时，先对齐算法外部条件：传感器模型、地图分辨率与概率更新、机体占据膨胀、目标容差、到点保持、碰撞记录、起降和停止确认。用确定性检查固定这些共享项，同时列出规划核心、探索/备份能力和滚动策略等有意差异。共享地图实现不等于配置已对齐；GCOPTER 曾因私有副本膨胀0.4m而参考配置为1.0m，在森林中出现碰撞，对齐后才完成同链路验收。配置对齐用于建立公平输入和安全包络，不能把算法缺失改写为等价能力。

轨迹输出的yaw属于执行语义。若参考系统按速度定向，局部轨迹应从水平速度生成并跨采样解绕，在低速点沿用邻近有效方向；固定yaw可能让位置任务通过但无人机长期侧飞。滚动更新除P/V/A外还要检查交接处yaw连续，并在真实飞行记录中比较参考与实际航向。

含随机路径搜索的优化器，将搜索覆盖与数值等价分开：固定同一走廊和边界状态对照直接上游调用与封装调用的 duration/P/V/A，另测完整搜索的障碍与无解。GCOPTER 的 OMPL 入口会返回近似解，最终计划须核查确实到达目标；在生成凸走廊前拒绝空路径和未到达结果。

体素中心作为几何障碍点时，检查走廊是否侵入体素体积；GCOPTER 首轮障碍回归检出了优化轨迹落入膨胀占据格。半体素对角线的保守走廊余量在该固定用例通过，仍须使用原占据图独立采样复查并重跑平台闭环。该经验不证明任意分辨率或窄通道可行，也不把软惩罚约束当成硬保证。

长地图另查搜索分辨率和走廊连通性。OMPL默认运动检查间隔随全图范围增长；GCOPTER森林用例将间隔限制到半体素，并用长图薄墙回归验证。走廊收缩后逐项检查非空及相邻交集；本用例通过在搜索图额外预留一体素净空恢复连通，FIRI和终检仍使用原碰撞膨胀图。该保守方案可能拒绝窄通道，不宣称完备性。保存随机种子和实际耗时；固定种子下超时搜索仍受调度影响。

批处理静止起点的计划与执行承诺分开：求解完成后读取新鲜权威状态，核查起点偏移和静止条件，再显式建立未来执行基准。该步骤只适用于声明的静止边界，不适用于滚动轨迹的任意重定时。真实地图快照送达以 Function 的实际输入就绪为准，不能把 publish 返回视为订阅已消费。

求解耗时导致悬停起点漂移时保留原连续性门，先离线比较搜索预算/轨迹参数。计划速度上限应透传到Behavior Goal；适配器准入上限不是每条计划的执行上限。验收同时报告配置、参考和实测速度，规划软约束不能保证控制器没有超调。

**完成门：** 真实平台输入进入 Planner，计划被声明 Behavior/消费者实际消费，全部适用 Harness 测试有结论。

## 3. 注册与部署

使用 [`uav-package-component`](../uav-package-component/SKILL.md) 生成清单、Registry、卡片和交付状态。需要 RoboPi 时使用 [`deploy-lib`](../deploy-lib/SKILL.md)；PC 闭环与板端最小加载分别报告，后者不替代前者。

**完成门：** 交付声明与同一版本证据一致；失败、跳过和未执行项保留；复现结束后回顾并修订相关正式 Skill。
