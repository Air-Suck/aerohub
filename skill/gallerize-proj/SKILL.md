# Gallerize Proj

将一个算法项目整理成可核查的 Gallery 页面。先读仓库约定及 `gallery/README.md`，核对 Git 差异，保持增量修改。需要建立能力与进程映射时使用 `uav-architecture-analysis`。图中的层级按项目主架构表达职责，不改变实际进程与部署边界。

## 算法核心与框架分工

面向开发者与算法迁移者，默认阅读顺序为 **Demo → 场景特色概述与关键词 → 算法核心图 → 三层框架图 → 案例 → 折叠技术详情**。案例按任务要求填入真实材料；要求留空时只保留标题，不填占位案例。现有条目按明确任务范围增量迁移，不自动批量改写。

算法核心图从左到右阅读，左右两端用与内部模块不同的红色系节点标出算法整体输入与输出，并保留文字标签以支持无颜色辨识。核实目标、传感器、自身状态及必要约束，区分内部候选与最终输出；输入连到实际消费该数据的步骤。内部以实际方法组织节点、分支和反馈回路。核对源码中的输入、核心求解和输出，突出算法独有设计；外部感知、定位或执行只在必要时标为外部边界，不拼成算法自身的完整流水线。学习方法明确网络输出与后处理边界，备份轨迹明确与主轨迹的衔接关系。

三层框架图采用统一层级和图例，解释能力归属、调用和数据依赖。默认节点是能力，bridge、adapter、客户端、传输协议与进程拆分留在折叠详情。算法图允许各自不同，框架图保持规范；分层不表示独立进程。更新图后同步正文里的节点名、颜色及连线说明。

关键词写入条目 frontmatter 的 `keywords`；字段与数量约束读取 schema。核心图保存为条目 `assets/algorithm.svg`（需替换既有浏览器缓存时可使用带语义后缀的文件名，如 `algorithm-io.svg`），三层图为 `assets/layers.svg`，通过 Markdown 引用。窄屏使用可聚焦的 `.diagram-scroll` 区域，保持从左到右的结构和文字可读性，不把宽图压成不可辨识的缩略图。

## 三层架构视图

算法项目的图统一覆盖 **Tool / Behavior / Function** 三层。算法接入范围在 Tool 及以下，但覆盖哪些层需按实际接入核查，不能由算法名称或单一分类标签决定。按职责分别核查算法内核、目标调用、执行协调和基础能力，不能用最终输出类型或“通用 Tool 未实现”推断整个组件只属于某一层；Gallery 分类、源码目录和进程边界也不决定层级。分别记录上游提供的能力与本项目实际采用的模块，在各层区分项目提供的实现、调用的执行能力、复用的数据与基础能力。

- **Tool**：规划、适配、执行协调及其他任务能力。现有 Planner 链只能标为 Navigation Tool 的实现基础，通用 Tool 未实现时须注明。
- **Behavior**：实际调用或扩展的基础执行能力，主图表达执行能力，组件、Action、调用方与时机在补充信息交代。区分算法新增实现、公共扩展和原生复用。
- **Function**：状态估计、环境感知/建图、控制与传感器等基础能力。区分算法实际提供的能力与其复用的外部依赖；例如定位建图项目可以同时覆盖 State Estimator 与 Perception。

未涉及的层或能力明确留空或弱化标注；调用、依赖某层不等于实现该层。不强制所有算法绑定运动 Behavior。执行调用与共享数据分别连线，数据可跨层直读。平台在三层图外注明边界；Mission/Agent 仅按实际状态说明。颜色与图例明确标识算法接入、公共复用及未涉及项。

## 源码核查

1. 读取用户指定项目的 README、版本锁定、配置与入口，沿实际调用追踪到 proxy、adapter、机群协调器及 Behavior。记录来源文件和符号；子模块未检出或没有日志时明确缺口，不自动初始化上游、构建或运行算法。
2. 建立各层模块的输入 → 输出 → 责任表，核实实现覆盖、执行调用与数据依赖。标明起飞等前置调用是否由测试/部署入口负责；不要把它写成算法核心自己调用。
   地图维护也纳入 Function 职责核查：地图可以与规划在同一进程中，按职责跨层绘制时注明共享进程。追踪地图输入是实际测量、仿真生成还是占位数据。共享代理不能作为集中式规划的证据，应继续核查逐机规划实例及广播关系。
3. 对多机项目，核实共享规划次数、车辆 ID/namespace、目标归属、轨迹时间与坐标转换、共同基时间、逐机 Goal、确认期限和失败收口。说明配置声明规模、展示规模和实际验收规模的区别；逐机调用不等于自动同步。
4. 区分源码核查、历史验收记录和本次运行证据。默认不运行 ROS、仿真或飞行任务。页面的验证等级遵循已有 schema，不能把结构图或配置目标解释为实际轨迹/测量结果。
   同步验证说明时读完组件 README 的后续专项记录，将“未执行”“已执行但失败”“安全门阻止后续测试”分别表述。历史文档引用的证据包在当前工作区缺失时，保留文档报告及失败门限，明确本次未独立复核；公开证据不足时元数据继续使用 `unverified`。
   按运行入口分别核对实际执行后端；legacy setpoint 的混合部署通过不能用于证明默认 FollowTimedPath 链已在同一拓扑验收。分别标明运行拓扑与目标部署：板端短程闭环不证明工作站任务调用已拆分，也不证明通用 Mission/Tool 已实现。以实际构建入口及来源记录确定算法实现版本；参考 upstream gitlink 不能替代主仓库 native 源码版本。无公开运行证据时，正文可引用主文档报告的限定结果，元数据仍使用 `unverified`。

## 上游视觉素材筛选

为条目搜集素材时，从锁定上游 README、仓库资源和链接到的项目网站出发，查看应用照片、演示动图、平台展示及方法示意；论文素材暂不纳入默认搜集范围。逐项实际查看画面后，按其说明作用采用，不按固定数量填满版面。网络不可用时可先使用本地锁定素材，明确未完成网站检索和视频在线核验，不声称已遍历官方来源。

视频优先 Bilibili；同一演示有多个平台时，将 Bilibili 写入 `demo.video`，其他平台写入 `videos` 备选。分别判断作者来源、内容匹配度与完整性；转载标注转载，不把同名或相关介绍当作官方演示。视频链接应来自上游明确链接或已核查的作者页面。

素材保存在条目 `assets/`，在 `assets/SOURCES.md` 记录上游版本、原始路径、作者归属、转换方法及许可条件，保留所需版权声明。逐项区分实机、仿真、方法示意和本项目结果；合作应用不能写成当前已接入能力。大 GIF 可等比转为动画 WebP，隔帧采样须累计帧时长保持速度；实际查看转换结果。动画用原始资源 URL，避免图片优化将其静态化。

## 桌面优先的素材编排

为已授权条目配置 `showcase`，按以下顺序整理；完整字段、示例和 Markdown 卡片结构见 [Gallery 使用文档](../../gallery/README.md#桌面优先的素材展示)。当前已应用 SUPER / YOPO；未授权条目沿用既有布局。

1. 顶部左侧主视频约 70%、右侧精华说明约 30%，视频保持比例。`headline` 点出核心设计，`highlights` 用少量具体说明解释机制，`keywords` 放在右侧文字下方；合并重复开场段落，尽快进入算法核心。主视频使用可点击封面跳转平台，保留其他视频的小型链接入口。
2. 应用、场景、平台素材放 `media`，每张左图右文，桌面一行两张；一行放得下时隐藏翻页控件，超出时横向分页，支持按钮、滚动与方向键，不自动轮播。手机每页一张。媒体区域高度固定、contain 保留完整画面，不能因方形图、切页或播放撑高整排。
3. 动图默认静态 `image`，点击后原位加载 `animation` 持续循环，播放图标消失，不添加开始/收起按钮或控制条。文字讲应用价值，不只复述画面。
4. 算法核心中的上游方法图也使用相同边框、比例和媒体高度的左图右文卡片，桌面并排；每张解释一个方法要点，避免大图加重复总图注。静态图保留在正文 `.method-cards` / `.method-card` 中，自己的算法核心图与三层框架图继续保留。
5. 整个展示模块底部仅出现一次简短上游结果声明，具体出处与合作署名收进“来源”。`demo.source`、`media[].source`、`showcase.methodSources`、`showcase.sourceNote` 分别登记相应来源；本地来源清单保留版本与许可详情，页面不重复堆免责声明。

完成条件：每项素材已实际查看、精华说明与归属准确、关键词保留、所有资源和来源可追溯；随后按 bundle-gallery 验收，不以网页展示升级算法验证等级。

## 内容落盘

- 页面优先呈现 **Demo → 场景特色与关键词 → 算法核心图 → 三层框架图**；源码路径、接口表、部署差异与验收记录放在后面的补充信息，必要时用折叠区域保留细节。Demo 使用作者官方仓库 README、项目主页或作者视频中的代表性素材；接入参考 fork 与原作者仓库分别标注，保留来源和图注；紧凑展示按前节统一声明与来源，不将上游效果写成本项目实测。
- 获取素材时核查实际内容、大小及复用条件。大体积 GIF/视频可用作者视频的轻量封面链接原演示；注明点击入口，保留原始来源，不把上游 Demo 当作本项目验证证据。可复用的小型封面优先放条目 `assets/` 并随站点构建，避免首屏依赖外部图片域名；正文保留原图 URL、作者来源及必要许可信息。条目 frontmatter 的 `demo` 支持本地内容路径或远程封面、替代文字、图注、来源及视频入口，字段以 `gallery/schema/algorithm.ts` 为准。
  实际查看候选素材后再选用，优先能说明场景或结果的画面。视频默认缩略图仅含标题时，可继续查作者 README 或项目网站的场景封面，保留具体出处；不拿其他工作的效果替代。使用本地图像的原始宽高设置展示比例，不将所有素材强制视为 16:9。封面点击跳转官方演示，图注仍须区分上游效果与本项目验收。
- 页面顶部用官方仓库、官方视频入口替代源码版本和验证记录信息表；迁移阶段用灰色“未迁移”、橙色“迁移中”、绿色“已接入”标记，保留文字以支持无颜色辨识。迁移阶段不代表验收等级，版本与验证细节保存在补充信息和数据中。
- 所有网页内容与资源写入 `gallery/content/algorithms/<id>/`：`index.md` 保存 frontmatter 和正文，`assets/` 保存条目专属图示等小型资源。
- 在 `gallery/content/gallery.json` 的 `items` 中追加稳定 ID 与 `content/algorithms/<id>/index.md`，已有 ID 则原位更新，避免重复。
- 源 Markdown 可从仓库其他目录读取，但网页不得直接加载外部源文件；保留源文件原文。所有网页构建、监听和静态产物均限制在 `gallery/` 内；Skill 实现保存在 `skill/`，通过 `.agents/skills/` 的独立相对软链接按需启用。
- 默认使用现有模板。用户明确授权展示结构调整时，可增量修改共享模板、schema 与必要样式；可由 Markdown 承载的算法专属图文仍保存在条目中，保留其他条目的展示行为。

正文需要能回答：项目做什么；Tool、Behavior、Function 各涉及什么；哪些由项目提供、哪些调用或复用；多机如何实例化与协调；哪些事实已核实、哪些尚待验证。结构按项目选择，不机械复制不适用章节。

## 图示与视觉校验

开始绘图前必须完整读取 [图示风格与职责参考](references/diagram-style.md)、其 token 和两个 SVG 模板，并实际渲染查看模板及指定基准；按该参考做职责证据表与跨图并排验收。不能仅凭本文件的文字描述自行另起配色或将项目案例当作通用拓扑。

SVG 保持原生可编辑，配标题、描述、Markdown 替代文字与对应文字说明。没有实际运行产物时使用结构示意。

1. **聚合重复实例**：Behavior、Function 等各层中，职责与接口一致且数量大于一的逐机实例优先用 `×N` 表示，并注明车辆或 namespace 范围；单机或单个算法实例直接显示名称，不标 `×1`，必要时用说明文字交代共享进程。共享规划与协调只画一次；不同实现或调用关系分别画出。`×N` 表示独立实例数量，不表示一个进程，也不证明多机同步或该规模已验收。
2. **预留连线路径**：执行请求、结果数据和共享状态按图例区分。箭头接到节点边界，使用侧边或层间留白；连线避开全部节点文字、层标题、注释及无关节点，防止形成错误连接。需要连通的分支标出接点。
3. **渲染并查看**：SVG 修改后实际渲染并打开图片，检查文字裁切、线条遮挡、箭头归属和图例一致性；缩放到页面预计显示宽度检查可读性。同时检查桌面与窄屏中的图例、文字和可滚动区域；每次调整后重新渲染查看，直到所有涉及节点与连线均可清楚辨认。XML 校验和构建成功不替代视觉校验；未实际查看时须如实报告未校验。

可使用 Gallery 已安装的 `sharp` 将 SVG 渲染为 PNG，写入仓库根目录 `log/gallery-review/`，再用图片查看工具打开。字体缓存不可写时将 `XDG_CACHE_HOME` 指向可写临时目录。预览须保留中文字体；缺字的渲染不能用于确认排版。证据图片属于运行产物，不复制进算法资源目录；正式 Skill 不依赖这些临时图片才能执行。

参考已核查案例：`gallery/content/algorithms/cat_ora/index.md` 及 `assets/layers.svg`。案例的版本、机数、坐标约定和验收结论只适用于该项目，不作为其他算法默认值。

其他三层图案例：`swarm_formation/assets/layers-capabilities-unified.svg` 展示逐机规划与共享协调，`super/assets/layers.svg` 展示同进程规划/地图及单机执行，`fast_livo2/assets/layers-capabilities-unified.svg` 展示仅 Function 接入与共享算法的两路输出，`ipc/assets/layers-unified.svg` 展示 Tool 侧 Demo 导航协调、FollowReference 会话执行与 Function 联合求解。按待展示项目选择参考，不复制案例的实例数量、运行后端或验收结论。

## Bundle 与交付

读取并执行同目录体系中的 `bundle-gallery` Skill，默认完成内容后自动本地 bundle。新增条目必须在用户正在使用的开发服务中核对列表链接与详情正文，执行 bundle-gallery 的注册热更新测试；只检查临时 dist 预览不能交付为当前页面已入库。检查 Gallery 列表、详情、图示资源及站内链接，确认沿用现有视觉风格，且未涉及条目未发生内容回归。用户正在验收开发页面或报告显示缺失时，执行 `bundle-gallery` 的“当前页面未更新时的排查与交付”，直接验证其服务中的 Demo 节点、图片响应与截图。交付时分别说明构建结果与实际视觉检查结果，给出预览产物路径及任何未检查项。开发服务的启动与效果验收按用户约定执行；本地静态构建和图片渲染不要求启动常驻服务。汇报源材料、三层覆盖与依赖、验证范围及待办；不自动推送或发布。

完成后把本次可复用的展示约束回馈本 Skill。算法复现经验归对应架构/适配/验证 Skill；仅做页面整理时不升级算法验收结论。

## YOPO：规划与 Inference 分离的展示

网络推理单独部署时，三层图将 Inference 标为 Function，将候选选优、轨迹重建与滚动执行协调归 Tool。明确网络输出是候选终端状态/评分还是完整轨迹，不能因网络内部编码了环境就标为对外建图能力。请求与候选返回分别连线，跨层线优先走外侧或节点间走廊，避免穿过未参与该调用的起降 Behavior。速度配置与实测速度分开记录；短程重复与长距离单轮分别限定，不扩大验收结论。
