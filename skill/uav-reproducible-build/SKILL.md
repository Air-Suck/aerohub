# 算法可复现构建

## 核查输入

先读项目约定和现有 Docker/Compose，核实源码位置、Git 状态、子模块、基础镜像、架构、编译器、ROS 版本与磁盘。以用户指定的工作区和提交为准，跨工作区同步前核对差异。构建脚本名字不是可从空机复现的证据。

日常迭代默认复用固定共享工具镜像，在持久工作区补编译并显式加载 overlay；接口/ABI 变化连同受影响消费者重编译。基础依赖升级、镜像快照维护与源码迭代分开；先确认本轮是否需要修改镜像，现有入口的限制单独记录。

## 构建决策

1. 上游源码用完整提交锁定，保留许可。联合算法只保留一份源码。独立构建环境按实际 ROS 依赖拆分，不强行混装发行版。
2. 明确所有基础镜像来源和构建入口；本地已有但仓库无法生成的镜像列为前置依赖，不宣称完整独立复现。交付记录镜像 ID/digest、平台架构及源码状态。
3. 依赖使用可解析版本和校验和。短提交失效时核查 API 需求和历史兼容性，说明替代依据；不能静默改为最新。vendor 归档保留来源、许可、锁定提交和 SHA256。
   Python 算法不能只锁顶层 requirements：从一次成功环境提取完整解析版本，形成受跟踪的 lock/constraints，并核对镜像内实际分布与锁文件无缺失、额外项或版本差异。目标 ROS 发行版自带 pytest/插件时，显式验证 pip 升级后的 hook 兼容性；算法库声明 `pytest>=...` 可能把 Humble 的 `launch_testing` 升坏。
4. 算法自身的正确性问题在实际构建源码中修复并提交：主仓库管理的 `ros2_adapter/native/` 直接提交；实际依赖维护的 fork 时再更新 gitlink。参考 `upstream/` 与实际构建输入明确分开，版本锁定用于追溯，不代表禁止修改源码。需要构建侧兼容补丁时应用到构建副本，检查上下文与版本匹配。区别算法输出语义修复和编译兼容修复。不要为了编译成功删掉算法所需能力。

   将 fork 转为补丁时，验证子模块目标提交实际可获取；主仓库能克隆不代表依赖已发布。完整 Git diff 可能包含空文件删除、文件权限和重命名，使用 `git apply` 并核对应用后的完整源码树，不仅检查编译文件；普通 `patch` 可能遗漏这些元数据。区分 fork 的上游基线更新与作者新增修复，避免误判改动范围。
   将已验证补丁移回算法源码时，核对完整改动与验收时的代码一致，删除重复应用步骤，并记录实际源码归属和提交。实际构建仍依赖算法子仓时，先发布依赖提交，再发布引用它的主仓库提交；主仓库自有native源码不要求发布参考子仓的新提交。
5. 核对 Docker COPY、依赖安装、colcon/catkin 包选择和测试范围；新目录不会自动进入镜像。限定构建并发，说明 native CPU 优化的移植限制。
6. 构建并执行与改动相应的安装/加载检查。明确命中缓存意味着相关测试未重跑；需要重新验证时有针对性地失效缓存。

远程启动长构建时记录客户端、远端 build 进程和 BuildKit executor 的归属。SSH 中断不保证远端 executor 已停止；重试前按 PID、命令、工作目录与启动时间核对，只终止本任务遗留的精确进程，避免多个大依赖下载并行或误伤其他构建。正式编排应使用可回收的进程组和有界清理。

需要构建应用快照镜像时，将 AS2/PX4 基础镜像作为显式 build arg，而不是默默引用旧发布标签。记录最终基础镜像 ID、应用镜像 ID 和 Dockerfile 的参数；检查镜像内部的安装前缀、消息包和算法节点。多阶段构建的 native 编译镜像与运行镜像都要核实，后者存在不代表前者编译了当前源码。构建成功仍不等于仿真或飞行成功。

完整锁定的 GPU Python 环境可能包含数 GB wheel；一次缓存未命中会使小源码改动也重新下载全部依赖。构建前确认 Docker daemon/BuildKit 实际代理配置与连通性，保留可追溯的 builder cache，或为固定 lock 准备带校验和的版本化 wheelhouse。缓存与 wheelhouse 只优化获取过程，最终仍要核对镜像内实际分发包与 lock 完全一致；不得为缩短重建而删减运行依赖或放宽版本。

现有子模块 checkout 与 gitlink 不一致时，先保存实际版本和修改；可将主仓库提交及所需 gitlink 源码导出到独立构建上下文，逐项记录来源和后续补丁。运行入口记录的工作树版本与实际构建输入分别标注，不能将旧 checkout 的 HEAD 当作新镜像的来源。先独立编译原生算法，再编译接入层；是否封装应用快照由交付需求决定，便于区分依赖、算法和接入层失败。

目录迁移时区分仓库相对路径、ROS 包名和镜像内安装路径，不能全局替换同名字符串。移动 ROS 包后同时核查 Docker COPY、colcon 包发现、测试依赖、Compose 构建上下文及 Python 的仓库根路径计算。`.gitignore` 不会自动取消已有产物的 Git 跟踪；迁移日志时保存原始内容并检查索引。

将算法源码从参考子模块纳入主仓库时，保留来源、导入提交、许可证和逐文件基线；只复制实际依赖的包。构建与运行清单指向 native/bridge，参考子模块只记录 gitlink，不要求初始化。使用不含该参考源码的干净上下文构建，并实际加载原生节点和适配器，检验是否还藏有旧路径依赖。

## 产物与交付

涉及 CUDA 模型迁移、独立 uv 环境、权重准备或模型 README/setup 维护时，先读取并执行子 Skill [model-migration-cuda](../model-migration-cuda/SKILL.md)，再继续本节交付。具体流程仅在该子 Skill 维护。

记录 build/install/log 在镜像、容器层还是宿主挂载；长期日志放 `log/<任务>/`，源码留在仓库。镜像重建不会自动更新已有容器，restart 也不切换镜像；替换运行实例属于部署阶段，按授权和任务状态执行。

交付可执行命令、Dockerfile/Compose、版本与依赖来源、补丁、构建测试日志索引和已知前置条件。失败尝试记入 `skill/temp/<任务>/`，把已验证的修复回馈 Skill，不把某一算法的旧依赖版本规定为所有算法默认。

## FAST-LIVO2 中可复用的经验

曾遇到非模板 Sophus 与最新版本 API 不兼容、文档短提交失效、AS2 安装头文件未导出 include 路径。应分别检查 API 历史、固定替代版本、从包前缀定位头文件，而不是全面修改 AS2 或依赖用户机器残留环境。算法和插件镜像构建成功不意味着飞行闭环成功。

## 固定共享镜像中的接口补编译

按仓库固定共享镜像约定，记录不可变 image ID，在外部工作区用同一镜像编译所需
接口 overlay；运行时只读挂载并 source overlay，不默认重建镜像或修改系统包。
接口源须与执行端 manifest 逐文件对齐，显式检查 Python 类型支持。已有目标端
依赖仅有规范 msg/srv 定义时，可记录版本/哈希并在工作站重新生成类型支持；
不得复制不同架构的动态库。缺包与便利 API 缺失分别处理。编译前后核对镜像 ID，
记录外部工作区、源文件与生成构建胶水；该工作区不作为源码的唯一保存位置。

ROS shell 环境脚本不一定支持 Bash nounset。入口可在 source ROS/AS2/colcon setup 时暂不启用 `set -u`，加载后再启用；用真实目标镜像构造节点，而不只做 Python 语法检查。Python ROS 节点避免以 `handle`、`clients` 等 Node 只读属性命名自己的状态；目标 rclpy 的真实构造检查能检出这类问题。

## ProjectAirSim Unreal 构建

对 UE 5.2.1 / ProjectAirSim `92032a6` 已验证：显式传入 `UE_ROOT`，确保
SimLibs 与 Unreal 插件使用同一 UE Clang/libc++；记录实际提交，`v1.1.0-N`
不能标成正式 v1.1.0。首次 Release ExternalProject 可能重复克隆 Debug 已有依赖。
下载停滞时先停止并核对本轮进程；复用源码前检查锁定 tag/commit、工作树与全部
子模块，保留中断目录，Release 库仍重新编译。克隆完成标记只在这些检查后更新。

分别保存 Build、Cook、Stage/Archive 和运行结果。若 Stage 调用 `env` 时被 PATH
中的不可执行同名文件挡住，可仅为本轮设置系统 PATH；Build/Cook 已通过时用
`BuildCookRun -skipbuild -skipcook` 续做原配置的 Stage/Archive，避免再次 `-clean`。
打包前后检查磁盘余量。运行验证至少核对服务返回的构建提交、场景加载与真实
传感器消息；离屏传感器冒烟与有屏 PX4/AS2 飞行验收分别报告。

ProjectAirSim ROS bridge 使用 `simulator/projectairsim/build_bridge.sh`：只把 ROS 包
暂存到外部 workspace/src，应用仓库版本化补丁，C++ client 以
PROJECTAIRSIM_CPP_CLIENT_DIR 指向只读上游。固定 ROS 工具镜像中构建、测试，
保留独立 install overlay；不为补丁重建共享镜像。切换已缓存源码路径时用新
workspace，避免 CMake source-dir 不一致。脚本实际构建及 colcon41汇总测试已通过。
