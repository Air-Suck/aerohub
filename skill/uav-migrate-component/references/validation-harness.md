# 验证 Harness

## 成熟度

1. `source-locked`：源码、提交、许可证和能力边界可追溯。
2. `baseline-verified`：上游固定成功与失败用例可重放。
3. `build-verified`：目标环境从声明输入构建并调用真实核心。
4. `interface-verified`：目标接口、空间、时间、版本和失败语义通过。
5. `platform-input-verified`：真实平台状态、地图或传感器被核心消费。
6. `downstream-verified`：声明的消费者实际消费目标输出。
7. `closed-loop-verified`：预声明 AirSim + PX4 SITL 正常任务通过。
8. `reproduced`：全部适用正常、边界、故障与恢复测试通过，证据完整。

后一状态不覆盖前面的失败；适用项失败、跳过或缺证据时停止升级。

## 共用矩阵

| 类别 | 最小检查 |
| --- | --- |
| 来源与构建 | 提交、dirty diff、许可证、补丁、依赖、安装与真实核心加载 |
| 数值 | 固定成功/失败输入、输出结构、约束、容差与性能方法 |
| 接口 | 实际类型支持、frame、时间、QoS、版本、无效输入与失败结果 |
| 输入 | 实际发布者、真实样本、核心消费、新鲜度和 reset |
| Function | ready/health、请求或持续输出、超时、并发、退出与恢复 |
| Behavior | Goal、反馈、结果、更新、取消、输出静默和控制交接 |
| 下游 | 真实消费者、无旁路、资源所有权和冲突处理 |
| 任务 | 正常场景指标、完成、停止、降落与 disarmed（适用时） |
| 故障 | 输入断流/延迟、核心退出、无解、迟到、执行拒绝及恢复 |
| 清理 | 本轮进程、容器、发布者、端口和平台状态收口 |

## 证据

在 `log/<对象>/<运行标识>/` 保存源码与 dirty diff、镜像、配置、种子、命令、节点/接口/TF/时钟连接、bag/平台日志、故障时间线、指标与阈值、结果、工件校验和及复验入口。失败轮与修复轮使用独立目录。

需要运动时证明指令经过 AS2 与 PX4，不用 AirSim 运动 API。使用真实模型和 GPU 的能力执行真实算法；合成输出、CPU mock、服务存活和视频均不能替代对应证据。
