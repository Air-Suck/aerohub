# ROS 接口与版本适配

## 选择方案

平台数据源选择、传感器扫描模型和物理测量语义适配由 [平台传感器适配](../uav-platform-sensor-adaptation/SKILL.md) 负责；本 Skill 聚焦 ROS 版本与传输实现，并确保这些已定义语义在桥接中不丢失。仅涉及 ROS 发行版迁移时，无需额外进行平台传感器改造。

读取项目约定，确认算法和 AS2 的实际 ROS 发行版、操作系统、消息版本和输入输出。区分 ROS 1→ROS 2 与 ROS 2 发行版差异，不默认都需要桥接。

比较配置/remapping、兼容桥接、独立进程加专用 Adapter、源码移植的成本与语义完整性。选择能保留所需字段、时序和性能的最小方案；记录未覆盖的方向。例如仅实现算法输出桥，不意味着 ROS 2 原始传感器已能输入 ROS 1 算法。自建 TCP 桥只是备选，不能把某次成功案例变成通用默认。

## 必查契约

| 方面 | 检查与处理 |
| --- | --- |
| 字段 | 检查实际赋值代码与运行样本；消息类型相同不代表字段已填。说明缺失值、单位、协方差含义与有效性 |
| 时间 | 区分采样、积分终点、估计时刻、发布与接收时间；核对时钟域、延迟、偏移、回放 `/clock` 和 reset。不得通过改为 now 掩盖时延 |
| 空间 | 明确 ENU/NED、FLU/FRD、父子帧和旋转方向；说明外参 T_A_B 的方向与标定来源。改 frame_id 不能代替数值变换 |
| 速度 | 确认表达坐标系和参考点；从 IMU 原点转机体原点时检查角速度与杆臂项 |
| 传感器 | 检查 IMU 测量来源、点云字段和逐点时间、扫描格式、图像编码、内外参、畸变与同步；示例标定不是实机标定 |
| 传输 | 检查自定义消息、QoS、队列、数据率、包大小、断连与重连；状态避免重连后重放过期缓存，地图/录包是否允许丢帧另行声明 |
| 发布权 | 命名空间、TF、时钟来源和权威状态源唯一性；桥不擅自替代原有发布者 |

## 实现与检查

ROS 骨架调用独立 HTTP 模型 worker 时，ROS 接口仍保留观测时间和 frame；HTTP 仅为内部实现，不作为替代 ROS 的对外能力入口。深度 `32FC1` 米与 `16UC1` 毫米需处理行 stride、端序和无效像素；模型 worker 不负责隐式 TF 或时间同步。返回结果保留输入状态 header 和请求标识。HTTP 超时不等于计算已取消，worker 在实际计算完成前保持忙，避免仅凭客户端超时就释放执行槽。

用必要的非恒等坐标样例、已知角速度和杆臂验证变换，检查时间戳保留、无效值与陈旧输入、桥断连恢复、点云二进制布局。测试应覆盖实际消息链路，不只调用转换函数。校准和输入缺失时报告条件，不虚构参数或精度。

上游实时 wrapper 不是可信契约来源：逐项检查它是否用输入采样时间、是否填写速度、跟踪失败时是否仍发布，以及 ROS 2 消息对象能否被核心读取。若核心可直接消费 PointCloud2 数据布局，优先编写原生 ROS 2 Adapter 而不是为 ROS 1 wrapper 建桥。上游只输出离散 pose 时，可在 Adapter 用相邻有效样本和真实采样间隔计算明确表达坐标系的有限差分 twist；首个样本没有速度依据时不发布完整状态，不能填零伪装就绪。跟踪丢失、处理异常、重置或全局回环修正会破坏相邻样本连续性，必须重置有限差分基线并等到新的连续样本，不能把位姿跳变伪装成速度；仍不得宣称全局修正输出同时是平滑局部 odometry。

对 XYZ-only 仿真点云，先核对算法选用的具体预处理器：ring、逐点时间或强度缺失时，不以补零和 PCL 转换成功作为兼容证据。某些驱动处理器会在时间缺失时按扫描角速度推算；必须核实仿真扫描方式、顺序和时间单位是否符合该模型。瞬时整帧数据与旋转扫描数据应明确区分，必要时适配预处理入口或传感器输出，并用运动场景验证；不得伪造测量时间或把合成测试配置直接作为真实传感器配置。

PointCloud2 兼容还要检查解析器的运行依赖而不只看消息字段。例如解析模块可能在类型常量处依赖 `rosbags`，即使实际传入的是 `sensor_msgs/msg/PointCloud2`；这类隐式导入须进入锁文件并通过镜像内导入测试。

交付版本兼容方案、方向明确的接口表、适配代码/配置、可重放测试及限制。端到端功能与故障恢复验收由验证流程完成。过程记录进入 `skill/temp/<任务>/`，日志进入 `log/`，收尾回馈已有 Skill。

## 已有案例

FAST-LIVO2 的 ROS 2 锁定实现通过专用 Adapter 规范帧、时间、QoS、瞬时 LiDAR 和重复点云，再由原生 AS2 插件接入，不能仅 remap 到 raw_odometry。算法世界坐标必须转换到平台控制所使用的 canonical `odom`；若点云需要保留算法原生世界，则通过带实际旋转/平移的静态 TF 关联，不能发布恒等别名。该结论来自特定版本，接入其他版本仍须重新核查。

## 跨目标 Python 接口检查

ROS 参数测试须包含 `Parameter.to_parameter_msg()` / `from_parameter_msg()` 往返，
或实际服务调用；DOUBLE_ARRAY 在目标 rclpy 可能返回 `array.array`。按 ROS 参数
类型及长度/有限性校验，不用 Python list/tuple 白名单误拒绝线上请求。运行期
目标变更须同时更新节点缓存，并限定执行已停止/静默状态。

固定共享镜像的 rclpy 可能没有便利客户端模块。先检查实际导入，必要时直接使用
标准 `rcl_interfaces/srv/SetParametersAtomically`，等待响应成功后再运动；不能因
便利 API 缺失就替换共享镜像。类型支持加载和无运动构造通过仍不等于跨机连通。

## 测量时间与未来参考时间

参考规划接口分别携带图像采集、实际定位观测及规划参考起点时间。仅参考起点允许有界未来；实际测量仍拒绝未来/陈旧输入，响应保留请求ID与两个时间头。目标世代变化或计算过期时丢弃响应，保持真实未结束请求占用，避免客户端超时造成请求叠加。对采样时间先在 ROS Duration 的纳秒网格生成唯一递增值，再构造曲线；`5.000000000000001` 与 `5.0` 会序列化成同一时间，导致执行端正确拒绝。保留该浮点边界回归，检查量化后的严格递增性。

使用目标 rclpy 和实际 TF 传输验证先消息、后TF的顺序；lookup_transform瞬时失败不能直接丢弃持续输入。请求已冻结快照后，新的图像暂时缺匹配状态不应使旧请求失效；响应检查冻结快照本身的年龄、任务世代与截止预算，同时检查当前定位健康。

## 优化状态的时间语义

关键帧、滑窗或回环算法输出的“最新优化状态”不一定对应当前输入。Adapter 必须把算法内部关键帧索引映射回原始观测时间，只在出现新的优化状态时发布一次；不得用当前输入时间或发布时间给旧关键帧重新盖章。需要与里程计、IMU 或其他状态配对时，也应按该关键帧的真实时间查询历史样本。用非等速输入回归验证索引、时间和状态对应关系，避免当前时刻的辅助状态与旧视觉位姿组成物理上不存在的联合状态。
